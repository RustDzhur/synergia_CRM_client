# Площадка агентов (Harness)

Всё про агентов лежит в одном месте:

| Что | Где |
|---|---|
| Определение Harness (Dockerfile, compose) | этот каталог, `deploy/agents/` в репозитории сайта |
| Секреты Harness | `deploy/agents/.env` на сервере (в git нет): `DSH_WEB_TOKEN`, `OMNIROUTE_API_KEY` |
| Рабочие папки агентов | `~/agents/<имя-агента>/` на сервере (внутри Harness — `/workspace/<имя>`) |
| Код сайта для агентов | `/site` внутри Harness, только чтение |
| Токены и права агентов | CRM → Настройки → Интеграции → «Агенты» (создать, отозвать) |
| Инструкция и API | `docs/AGENTS.md` |

## Новый агент за три шага
1. В CRM: Настройки → Интеграции → «Агенты» → имя + право → «Создать». Токен показывается один раз — скопируйте.
2. В Harness создайте агента, рабочая папка — `/workspace/<имя>`; положите туда `.env` (`FIRMSPACE_API=http://127.0.0.1:3210`,
   `FIRMSPACE_TOKEN=<токен>`) и текст задачи (пример — `~/agents/_template/TASK.md`).
3. Запустите. Отозвать доступ — кнопка «Отозвать» в тех же настройках, пересоздавать контейнеры не нужно.

Ссылка для входа в Harness (с постоянным токеном из `.env`): `./deploy/agents/url.sh` (снаружи) или `./deploy/agents/url.sh local`.

Запуск самой площадки: `docker compose -p dsh -f deploy/agents/docker-compose.yml up -d` (autodeploy делает это сам).
