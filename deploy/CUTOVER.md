# Переключение firmspace.de на сервер (порядок действий)

Дубликат уже работает: контейнер `firmspace-crm`, база PostgreSQL (`crm`), файлы на диске.
Ниже — что осталось сделать и в каком порядке, чтобы не было простоя и двойных уведомлений.

## 0. Что уже проверено

- `docker ps` → `firmspace-crm ... (healthy)`; `curl http://127.0.0.1:3210/api/health` → `{"ok":true,"db":"ok"}`;
- данные сверены с оригиналом: **53 из 54 таблиц совпадают по количеству записей**; разница только
  в `events` — там на одну запись больше, и это событие iCloud, которое **сам дубликат** подтянул
  при синхронизации календаря (значит расшифрованные токены интеграций рабочие);
- сессии переносятся: токен, подписанный `JWT_SECRET` оригинала, дубликат принимает;
- входящий IPv6 до сервера доходит (проверено внешним запросом: `ESTABLISHED` в conntrack на :80,
  счётчики ip6tables растут и на :80, и на :443) — роутер менять не нужно;
- Caddy: конфиг лежит на диске (`/etc/caddy/Caddyfile`) и содержит `firmspace.de → 127.0.0.1:3210`,
  ACME переведён на Let's Encrypt (ZeroSSL отключён — у него ломаются старые аккаунты Caddy).

## 1. DNS: одна запись

Vercel → Domains → DNS, добавить `AAAA` для `@` и `www`:

```
2a02:8071:6541:7120:be24:11ff:fe55:b584
```

Записи `A` **можно оставить** — тогда IPv4-посетители останутся на живом Vercel, а IPv6 увидят
дубликат: переход без простоя. Когда убедитесь, что всё хорошо, `A`-записи убираются (или
переводятся на другой адрес) — тогда дубликат обслуживает всех, кто умеет IPv6.

Через 1–3 минуты Caddy сам получит сертификат (проверка Let's Encrypt идёт по IPv6:80).

## 2. Проверка

```
bash ~/crm-duplicate/deploy/check-public.sh
curl -s https://firmspace.de/api/health        # {"ok":true,"db":"ok"}
```

Если сертификата нет дольше 10 минут — смотреть `journalctl -u caddy -n 50`.

## 3. Данные: финальный догон

Пока DNS ещё указывает на Vercel (или сразу после), изменения из оригинала нужно догнать:

```
cd ~/crm-duplicate          # код тоже нужен актуальный: git pull / повторная заливка
node .zz-migrate-mongo-to-pg.mjs --upsert      # с Mac, где доступен MONGODB_URI
```

Скрипт идемпотентный: обновляет существующие записи и добавляет новые. Удаления в MongoDB он
не переносит — если что-то удаляли в оригинале, это придётся убрать вручную.

## 4. Включить крон дубликата

```
crontab -e
5 7 * * * curl -s -m 120 -H "Authorization: Bearer <CRON_SECRET>" http://127.0.0.1:3210/api/cron/reminders
```

**Важно:** пока оригинал на Vercel работает, его собственные расписания (`vercel.json`) обрабатывают
те же задачи. Крон дубликата включается только вместе с переключением DNS, иначе клиенты получат
письма и уведомления дважды.

## 5. Откат

Вернуть `AAAA`-записи (удалить их) — трафик IPv6 снова уйдёт на Vercel, оригинал продолжит работать.
Никаких данных на сервере при откате не теряется.

## 6. После переключения

- перенести 17 файлов из Firebase Storage (нужны `FIREBASE_SERVICE_ACCOUNT` и
  `FIREBASE_STORAGE_BUCKET`): `deploy/copy-firebase-files.mjs --write`;
- добавить отсутствующие секреты, если нужны платежи картой, вход через Google и ИИ:
  `STRIPE_*`, `GOOGLE_CLIENT_ID/SECRET`, `META_APP_*`, `ANTHROPIC_API_KEY`/`OPENAI_API_KEY`, `ADMIN_EMAILS`;
- следить за AAAA: префикс IPv6 у DS-Lite может меняться — `deploy/update-aaaa.sh --write` в cron.
