# Design Spec: единый большой сайт firmspace.de («Интеграции в ваше ПО»)

Дата: 2026-10-23. Владелец: Rustem. Статус: утверждён дизайн (структура + техника), ожидает ревью владельца.

## 1. Цель и позиционирование

Один большой сайт на **firmspace.de** вместо разрозненных лендингов. Приоритетное сообщение:
**мы интегрируем автоматизации в существующее программное обеспечение клиента** (документы,
CRM-процессы, интерфейсы между системами, ИИ-обработка) — клиенту не нужно бросать свои
программы. Собственные продукты (Firmspace CRM, Bürokratie-Copilot) — опции, а не главный оффер.

Платформы не имеют собственных маркетинговых сайтов: по адресу платформы пользователь сразу
попадает на вход/регистрацию.

## 2. Источники контента (вырезки)

| Источник | Что переносим | Куда |
|---|---|---|
| `automatisation-landing-page` | hero, проблемы, 4 направления, how-it-works, benefits, ROI-калькулятор, FAQ, дизайн-система, cookie-consent, формы | главная + `/automatisierung/*` |
| `burokratie-landing-page` | полный контент лендинга копилота (workflow, DATEV, проблемы, security, ROI, FAQ, demo-форма) | `/buerokratie-copilot` |
| `crm_client` (components/website, content) | über uns, контакты, блог (статьи), legal-тексты (impressum/datenschutz/agb), фичи CRM для продуктовой страницы | `/ueber-uns`, `/blog`, `/legal`, `/firmspace-crm` |

Не переносим: рынки UA/UZ (Нова Пошта, узбекские платежи), партнёрку/рефералку CRM,
документацию CRM (остаётся в приложении), careers/team.

## 3. Карта сайта (de + en, next-intl)

- `/` — главная: hero «Автоматизация встраивается в ваши программы»; 4 направления интеграций;
  продукты как опции; how-it-works; benefits; ROI-калькулятор; FAQ; CTA → форма.
- `/automatisierung/dokumentenverarbeitung`, `/automatisierung/crm-workflows`,
  `/automatisierung/schnittstellen`, `/automatisierung/ki-verarbeitung` — направления.
- `/firmspace-crm` — продуктовая страница CRM (фичи, цены → «Individuelles Angebot»).
- `/buerokratie-copilot` — продуктовая страница Copilot (из лендинга, с demo-формой).
- `/kontakt` — форма заявки.
- `/ueber-uns`, `/blog`, `/impressum`, `/datenschutz`, `/agb`, `/cookies`.
- Канонические URL на firmspace.de; Open Graph; sitemap; robots.txt.

## 4. Формы и виджет (контракт)

- Формы (`/kontakt`, demo-форма копилота) → `POST https://crm.firmspace.de/api/webhooks/landing/<token>`
  с заголовком `Authorization: Bearer <token>`, поля по контракту `lib/landingLeads.ts` (name, company,
  email, message/processDescription, …). Клиентская+серверная валидация, honeypot, rate-limit,
  успех только после ответа сервера.
- Токены: создаются в аккаунте владельца через CRM → Настройки → Интеграции → «Формы с сайтов»
  (метки `website-contact`, `website-copilot-demo`). Заявки попадают в его CRM (контакт + сделка
  «New Lead» + уведомления).
- Виджет чата CRM (`widget.js`, data-token фирмы) — на всех страницах сайта; CSP допускает источник виджета.

## 5. Топология и деплой

- Новый приватный репозиторий **firmspace-website** (GitHub RustDzhur): Next.js 15 App Router + TS,
  next-intl (de/en), дизайн-система автоматизейшн-лендинга, output standalone, Dockerfile.
- Сервер: `~/firmspace-website` + compose-проект `firmspace-website`, контейнер `127.0.0.1:3260→3000`,
  env: `NEXT_PUBLIC_SITE_URL=https://firmspace.de`, webhook-токены, виджет-токен, rate-limit.
- Caddy:
  - `firmspace.de, www.firmspace.de` → 127.0.0.1:3260 (большой сайт);
  - `crm.firmspace.de` → 127.0.0.1:3210 (CRM);
  - `burokratie.firmspace.de` → 127.0.0.1:3240 (без изменений);
  - `automatisation.firmspace.de` → 301 `/automatisierung`;
  - `copilot.firmspace.de` → 301 `/buerokratie-copilot`.
- CRM: на host `crm.firmspace.de` корень и маркетинговые пути ведут на страницу входа
  (middleware/редирект; маркетинговый код CRM удаляется отдельным шагом, см. §7).

## 6. Rollout-порядок

1. Сборка контента и кода нового сайта (репозиторий + локальные проверки: build, тесты).
2. Деплой на сервер (rsync + docker build), контейнер healthy на 127.0.0.1:3260.
3. Переключение Caddy (пункт §5) + перезапуск caddy; проверка HTTPS всех доменов.
4. Smoke: формы → карточки в CRM владельца; виджет грузится; 301 работают; вход CRM по crm.firmspace.de.
5. Удаление лендингов: `docker compose down` проектов `landing-copilot`, `landing-automatisation`,
   удаление каталогов `~/landing-copilot`, `~/landing-automatisation` (их код остаётся в локальных
   папках и в истории нового сайта).
6. Отдельный PR в CRM: удаление маркетингового сайта (components/website, маркетинговые роуты),
   после стабилизации переключения.

## 7. Retirement (судьба старого)

- Лендинги: удаляются с сервера полностью (шаг 5); домены остаются 301-редиректами (без контейнеров).
- Маркетинговый сайт внутри CRM: фаза 1 — редирект на вход (обратимо), фаза 2 — удаление кода
  отдельным PR. Триггер фазы 2: сайт firmspace.de стабилен ≥ 1 недели без инцидентов.
- Откат: Caddy-конфиг возвращается в git-истории; контейнеры лендингов можно восстановить из
  локальных папок, пока они не удалены с машины.

## 8. Acceptance criteria (наблюдаемые)

- firmspace.de открывает новый сайт (de/en), все страницы карты отвечают 200, canonical на firmspace.de.
- crm.firmspace.de/ ведёт на вход/регистрацию CRM, приложение работает.
- Заявка с /kontakt создаёт контакт+сделку+уведомление в аккаунте владельца (проверено тестовой заявкой, данные удалены).
- Виджет чата виден на сайте; старые домены отвечают 301 на правильные разделы.
- Лендинговых контейнеров на сервере нет (`docker ps` без landing-*), каталоги удалены.
- Production build сайта и CRM зелёные; CI CRM зелёный.

## 9. Non-goals

- Не меняем приложение CRM и платформу Copilot функционально (только вход вместо маркетинга).
- Не переносим рынки UA/UZ, партнёрку, рефералку, документацию CRM, careers/team.
- Не публикуем SEO-тексты с выдуманными цифрами/отзывами (ограничения лендингов сохраняются).

## 10. Риски

- SEO при переключении доменов — смягчается 301 и canonical; блог переносится со слагами.
- Переключение firmspace.de в продакшене — выполняется точечно, откат через git-историю Caddyfile.
- Контент-объём (3 источника, 2 языка) — контент переносится как есть (без переписывания),
  перевод en — из существующих en-версий CRM-сайта и машинный черновик для новых страниц.

## ADR signal

Меняется владение публичной поверхностью: firmspace.de (маркетинг) отделяется от платформы CRM;
фиксируется расписание вывода из эксплуатации лендингов и маркетингового кода CRM. При завершении —
базовая синхронизация docs/ (INTEGRATIONS.md, README) и одна строка ADR, если владелец подтвердит.
