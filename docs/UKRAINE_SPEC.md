# ТЗ: режимы рынка DE / UA в финансовой части

Документ для модели-исполнителя. Составлен 2026-09-30 по аудиту кода (коммиты 1a49aca…1bb7952 и незакоммиченные правки). Правовые пункты помечены **[проверить]**: это не налоговая консультация, ставки и лимиты меняются каждый год — их нельзя зашивать в код, только в настройки с датой актуальности.

## 1. Цель и главные правила

1. Страна фирмы (`FinanceSettings.country`) определяет **режим рынка**: `DE` или `UA`. Интерфейс, документы, налоги и интеграции выбираются по режиму. Смешивать нельзя: в режиме UA не видно ни одной немецкой вкладки/кнопки/поля, в режиме DE — ни одной украинской.
2. Все украинские интеграции (Нова Пошта, Укрпошта, Checkbox ПРРО, monobank, LiqPay, WayForPay, крипта, Prom, Rozetka, Horoshop, OLX, курс НБУ) показываются и работают только в режиме UA. Данные подключений при смене страны **не удаляются**, только скрываются и отключаются их вебхуки/синхронизации.
3. Страна не выбрана (пусто) = экран «Выберите страну» при первом входе в Финансы; до выбора никаких вкладок, кроме настроек.
4. Все документы (рахунок, акт, накладная, ТТН-наклейка, чек) настраиваются в интерфейсе: реквизиты, префиксы, нумерация, тексты, логотип, печать/подпись, шаблон.
5. Сквозной процесс UA: заказ → счёт → оплата → чек ПРРО → доставка/ТТН → акт/накладная → книга доходов/налоги. Каждый шаг ведёт к следующему из интерфейса, без ручного переписывания данных.
6. Тексты только через `messages/{de,en,ua}.json` (R19). Строки в коде (как сейчас в `lib/finance/ua.ts` и API-ошибках) — вынести.
7. Секреты интеграций только зашифрованно (`packSecrets/secretsOf`), вебхуки только с проверкой подписи. Тесты — в scratch-копии, с моками и временными пользователями `zz-integr-test*@example.com`; коммиты и деплой только по слову владельца.

## 3. Архитектура: профиль рынка

Единый источник — `lib/finance/market.ts` (новый) и зеркало для клиента `useMarket()`.

```ts
type Market = "DE" | "UA";
interface MarketProfile {
  market: Market;
  currencyDefault: "EUR" | "UAH";
  localeDefault: "de" | "ua";
  nav: FinanceTabId[];               // какие вкладки Финансов
  documents: DocumentKind[];         // какие документы выпускаются
  integrations: IntegrationType[];   // какие плитки/кнопки разрешены
  taxModules: TaxModule[];           // отчёты и налоги
  features: { dunning, sepaQr, ... } // флаги
}
export function marketOf(country?: string): Market | null; // null → экран выбора
export function profile(market: Market): MarketProfile;
```

Правила:
- Сервер: каждый маршрут UA-функций (`/api/orders/[id]/waybill|ukrposhta|act`, `/api/invoices/[id]/fiscal|pay|payment-link`, `/api/marketplace/sync`, `/api/novaposhta*`, вебхуки оплаты, синхронизации по крону) вызывает `requireMarket(org, "UA")` и отвечает 409 «Функция доступна только для Украины», если режим другой. Аналогично немецкие (mahnwesen/BWA/SuSa/UStVA/EÜR/SEPA/Lieferschein) — `requireMarket(org, "DE")`.
- Клиент: меню, кнопки и плитки строятся из `profile(market)`, а не из `country === "UA"` по месту.
- Смена страны — отдельное действие с подтверждением: показывает, что скроется, предлагает применить набор по умолчанию (валюта, префиксы, срок, шаблон, ставки), ничего не удаляет. Существующие документы сохраняют свою валюту и формат.
- Сайдбар Настроек → Интеграции: украинские плитки видны только при `market === "UA"`; немецкие/общие (Twilio, Telegram, почта…) — всегда.

## 4. Интерфейс по режимам

**DE** (без изменений): overview, quotes, orders, contracts, invoices, recurring, dunning, expenses, assets, bank, products, UStVA, EÜR, BWA, SuSa, audit, settings. Документы: Rechnung, Gutschrift, Angebot, Lieferschein, Vertrag, Mahnung. SEPA/QR, Kleinunternehmer §19.

**UA**: overview, замовлення, рахунки, договори, акти, накладні, регулярні рахунки, витрати, банк, товари/склад, доставка (НП/Укрпошта), ПРРО (чеки/зміни), податки (книга доходів ФОП / податок на прибуток ТОВ / ПДВ-реєстр / звітність), аудит, налаштування. Без: Mahnwesen (замінити на «Нагадування про оплату» простой рассылкой — опционально), BWA, SuSa, UStVA, EÜR, Lieferschein, SEPA/QR, Kleinunternehmer.
Документы UA: рахунок на оплату (рахунок-фактура), акт виконаних робіт (наданих послуг), видаткова накладна, товарно-транспортна накладна (для перевозок, если нужна), податкова накладна (для платників ПДВ, через ЄРПН), рахунок-коригування, розрахункова квитанція/фіскальний чек.

## 5. Украинское законодательство (справочно, **[проверить]** перед реализацией и каждый январь)

Формы: **ФОП** и **ТОВ** (также ПП, ПрАТ — как юрособа; в CRM достаточно `fop | tov | other_legal`). Системи оподаткування:
- ФОП, єдиний податок, групи **1, 2, 3, 4** (4-я — сільгоспвиробники по площади/ставкам за гектар). Группы 1–2: фиксированная ставка от прожиткового мінімуму / мін. зарплати; группа 3: процент от дохода (3% с ПДВ или 5% без ПДВ — **[проверить]**). Ліміти доходу за год — по группам, меняются; вводятся в настройках с годом.
- ФОП на загальній системі: ПДФО + військовий збір, ведёт книгу доходів і витрат.
- ТОВ: загальна система (податок на прибуток) или єдиний податок для юрособ (3 группа, ставки/лимиты **[проверить]**).
- ПДВ: платник обязан зарегистрироваться при обороте свыше порога за 12 месяцев (порог **[проверить]**), может добровольно раньше; ставки **20%**, **7%** (отдельные товары, напр. лекарства/медизделия), **0%** (экспорт), «звільнено від ПДВ». Платник выписывает податкову накладну в ЄРПН (электронная подпись КЕП, сроки регистрации **[проверить]**).
- ЄСВ (ФОП «за себя» и за працівників), військовий збір.
- РРО/ПРРО: чек обязателен при **наличной/картовой** оплате физлицам и при расчётах в РРО-зоне; при безналичном платеже по рахунку между юрособами/ФОП — как правило, чек не нужен, достаточно рахунку/акта **[проверить у бухгалтера]**. Поэтому «пробить чек» — предложение, зависящее от способа оплаты и формы, а не безусловная кнопка.
- Первичные документи: рахунок, акт, видаткова накладна, ТТН/ЄН перевозчика — обязательные реквизиты: назва, ЄДРПОУ/ІПН, дата, номер, сума, підписи. Сума прописом — принято, не обязательна.
Всё выше вынести в `lib/finance/ua/rules.ts` с полями `validFrom/validTo` и источником; UI показывает предупреждение «Правила на {год}; сверьтесь с бухгалтером».

## 6. Профиль украинской фирмы (модель)

Расширить `FinanceSettings` (не ломая существующие поля):
`uaLegalForm: fop|tov|other`, `uaTaxSystem: single_1|single_2|single_3|single_4|general_fop|general_tov|single_tov`, `uaVatPayer`, `uaVatRegDate`, `uaEdrpou`, `uaIpn`, `uaVatCertificate`, `uaKved[]`, `uaIban`, `uaMfo`, `uaBank`, `uaSignerName/Position` + подпись/печать (изображения, в S3/Blob), `uaLimits[{year, group, amount}]`, `uaVatRates[{code:20|7|0|exempt}]`. Валидации: ЄДРПОУ 8 цифр, ІПН 10/12, IBAN UA 29 знаков (mod-97). Форма зависит от `uaLegalForm`: ФОП скрывает поля ТОВ и наоборот. Отсюда же выводятся налоговые модули (§9).

## 7. Настраиваемые документы

- Реестр шаблонов: `DocumentTemplate{ market, kind, name, blocks, texts{ua,en,de}, prefix, numbering, showStamp, showSignature, footer, paymentTerms, requisitesLayout }`. Хранить в БД по org, а не в `layouts.ts`. Готовые пресеты: UA-рахунок, UA-акт, UA-видаткова, DE-Rechnung… — копируются в org и редактируются.
- Экран «Налаштування → Документи» (в режиме UA): выбор документа, предпросмотр PDF по тестовым данным, поля реквізитів, нумерація (префикс/рік/лічильник, сброс), тексты (умови оплати, примітки), логотип, підпис і печатка, мова документа (ua/en), валюта.
- Генерация: ставка и сумма ПДВ по строкам, «Разом без ПДВ / ПДВ / Разом до сплати», сума прописом (укр. числительные, гривні/копійки), реквізити обох сторін, номер договору, КЕП-примітка не нужна.
- PDF и предпросмотр должны совпадать (один рендерер). Нумерация — атомарно (`nextNumber`), номер выдаётся один раз.

## 8. Сквозной процесс UA

1. **Заказ** (в т.ч. из маркетплейса/сделки): позиции с ПДВ-ставкой, склад-резерв (`StockMovement`), контрагент с ЄДРПОУ/ІПН, способ доставки и оплаты.
2. **Счёт**: создаётся из заказа одной кнопкой; курс НБУ на дату (если валюта ≠ UAH) фиксируется в документе.
3. **Оплата**: ссылка monobank/LiqPay/WayForPay/крипта или ручное «оплачено» / банковская сверка. Вебхук → статус «оплачен» → событие `invoice.paid`.
4. **Чек ПРРО**: по событию `invoice.paid`, если по правилам нужен (способ оплаты, форма), автоматически или в один клик; при кредит-ноте — чек возврата; смена открывается/закрывается (кнопка и Z-отчёт).
5. **Доставка**: из оплаченного заказа кнопка «Відправити» → выбор перевозчика.
   - НП: город/отделение или адрес, вес/габариты/цена, отправитель из настроек, получатель (телефон подставляется из контакта), COD = сумма счёта, если оплата при получении; **вызов курьера / забор** (`InternetDocument`+`PickupNumber`) с датой и интервалом; печать наклейки (PDF/ZPL) и накладной; удаление/редактирование до отправки; расчёт стоимости; статусы → статус заказа; возврат/перенаправление.
   - Укрпошта: создание отправления (`ecom`: клиент, адрес, отправление) → штрихкод → печать бланка; статусы. Договор и токены — от владельца; до появления доступа — мок и явная пометка «не проверено».
   - ТТН/штрихкод пишутся в заказ, отправляются клиенту (мессенджер/почта) и видны на публичной странице заказа.
6. **Документы завершения**: акт (услуги) или видаткова накладна (товары) — только один нужный тип по позициям заказа.
7. **Учёт**: оплата → книга доходов ФОП / доходы ТОВ; расчёт единого налога, ВЗ, ЄСВ; для платника ПДВ — строка реестра податкових накладних.
8. **Возвраты**: возврат оплаты → чек возврата → кредит-нота → отмена доставки/возврат на склад.

Каждый шаг — событие автоматизации (order_created, invoice_paid, waybill_created…), чтобы владелец мог подписать уведомления.

## 9. Налоги, отчётность, налоговая

- Единый налог ФОП: книга доходів (по оплате), проверка лимита группы (по `uaLimits`), предупреждение при 80/100%, расчёт налога/ВЗ/ЄСВ и календарь строков сплати; квартальная декларація — экспорт данных (PDF/XML по формату ДПС **[проверить формат]**).
- ТОВ загальна: податок на прибуток — доходи/витрати, звіт-заготовка; ТОВ єдиний податок — ставки/ліміт.
- ПДВ: реестр ПН/РК, декларація-заготовка, контроль порога реєстрації.
- **Подача в ДПС/ЄРПН**: требует КЕП, прямой публичный API для сторонних CRM отсутствует — реалистичные пути: (1) экспорт файлов (XML/CSV) для загрузки в кабинет ДПС/M.E.Doc; (2) интеграция с провайдером (Вчасно, M.E.Doc и т.п.) — нужны договор и ключи от владельца. Этап 1 — экспорт; этап 2 — провайдер. Явно писать в UI, что подача выполняется вне CRM.
- Никакой автоматической подачи без явного действия человека и без КЕП владельца.

# Часть II. Продвинутый модуль «Бизнес» (для DE и UA): склад, торговля, ВЭД, производство, данные

Цель: один компактный продукт вместо связки «1С предприятие + бухгалтерия + склад». Ориентиры по охвату — 1С, Odoo, Dolibarr (не копировать, брать логику). Всё подчиняется режиму рынка из §3: набор документов, налоги, бланки и справочники свои для DE и UA. Модули включаются по виду деятельности (мастер «Чем занимается фирма?»: услуги / розница / опт / производство / импорт-экспорт), лишнее скрыто.

## 12. Склад и торговля

- **Склады и остатки**: несколько складов и мест хранения; единицы измерения и пересчёт; варианты товара (размер/цвет); штрихкоды/QR; партии и серийные номера, срок годности; минимальный остаток и уведомления; резервирование под заказ; остатки по складам и в сумме.
- **Движения** (только документами, остаток не правится «руками»): приход (закупка), расход (продажа), перемещение, списание (брак/порча), оприбуткування излишков, **инвентаризация** (акт сверки, расхождения → документы). Каждое движение — неизменяемая запись, отмена сторно.
- **Оценка себестоимости**: средняя / FIFO (выбор в настройках, по умолчанию средняя); UA — по П(С)БО 9, DE — HGB §240/§256 (FIFO/Durchschnitt) **[проверить]**. Отчёты: оборотно-сальдовая по складу, карточка товара, остатки на дату, неликвид, ABC.
- **Закупки**: поставщики, заказ поставщику, приход по накладной, счёт поставщика → расход/кредиторка, возвраты поставщику, оценка поставщика.
- **Розница**: касса/POS (быстрая продажа по штрихкоду, наличные/карта, скидки, возврат, смена). UA — ПРРО Checkbox; DE — сертифицированная TSE (KassenSichV) и DSFinV-K экспорт **[проверить]**. Без сертифицированной фискализации розничная продажа в режиме «производство» запрещена — выдавать только счёт.
- **Опт**: прайс-листы и типы цен (розница/опт/дилер/по контрагенту), ступени по количеству, скидки, кредитный лимит и отсрочка, счёт-фактура/накладная, сверка взаиморасчётов, акт сверки.
- **Импорт/экспорт (ВЭД)**: инкотермс, HS/УКТ ЗЕД код у товара, страна происхождения, вес нетто/брутто, инвойс и упаковочный лист, мультивалюта с фиксацией курса.
  - UA: внешнеэкономический договор, митна декларація (данные для брокера), валютный контроль/строки розрахунків **[проверить]**, курс НБУ, ПДВ 0% на экспорт, ЄРПН при ставке 0%.
  - DE: ВЭД внутри ЕС — innergemeinschaftliche Lieferung (проверка USt-IdNr контрагента через VIES, Gelangensbestätigung, Zusammenfassende Meldung, Intrastat при превышении порогов **[проверить]**), Reverse Charge §13b UStG, третьи страны — Ausfuhrnachweis, EORI, данные для ATLAS. Всё — данные и документы, подача в таможню/налоговую вне CRM либо через провайдера.
- Заказ/счёт/накладная/чек — один документооборот: из заказа порождаются остальные, статус остатков и оплат виден на карточке заказа.

## 13. Производство (обязательно и для DE, и для UA)

- **Спецификации (BOM/рецептуры)**: состав изделия, полуфабрикаты (многоуровневые), нормы расхода с допуском/отходом, альтернативные материалы, версии.
- **Операции и маршруты**: этапы, рабочие центры/сотрудники, норма времени, стоимость часа.
- **Производственный заказ**: план → запуск → выпуск. При запуске резервируются материалы; списание материалов на производство (UA — вимога-накладна/акт списання; DE — Materialentnahme); выпуск готовой продукции на склад (UA — акт/звіт про виробництво; DE — Fertigungsmeldung), брак и побочная продукция, частичный выпуск.
- **Себестоимость**: материалы + труд + накладные расходы (база распределения настраивается), незавершёнка (WIP) на дату, факт против нормы. DE: Herstellungskosten по HGB §255, Bewertung Fertig-/Unfertigerzeugnisse; UA: калькуляция и виробнича собівартість по П(С)БО 16 **[проверить]**.
- **Планирование**: потребность в материалах под заказы (простой MRP), список закупки недостающего, загрузка мощностей.
- Отчёты: выпуск, расход материалов, отклонения, себестоимость по изделиям, партии сырьё → продукт (прослеживаемость).
- Связь: продажа изделия → при нехватке остатка предложить производственный заказ.

## 14. Правильность документов и требования закона

- Для каждого вида документа — **машиночитаемый чек-лист обязательных реквизитов** (`lib/finance/compliance/{de,ua}.ts`); документ нельзя выпустить (статус «оформлен»), пока чего-то не хватает; причина показана человеку.
- **DE**: §14 UStG (полные данные сторон, Steuernummer/USt-IdNr, дата, последовательный номер без пропусков, объём и дата поставки, нетто/ставка/налог, ссылки на освобождение), Kleinunternehmer §19, Reverse Charge, Gutschrift; **GoBD** (неизменяемость, журнал изменений, Verfahrensdokumentation, хранение и выгрузка для проверки), срок хранения [проверить], **E-Rechnung** (приём обязателен, выпуск XRechnung/ZUGFeRD по срокам законодателя **[проверить]**), **DATEV-экспорт**, Kassensicherung (TSE) для POS.
- **UA**: Закон про бухоблік (первинні документи: назва, дата, зміст операції, вимірники, посади й підписи), ПКУ (ПН, ЄРПН, ПДВ), ПРРО, ФОП/ТОВ-особенности; печать не обязательна, подпись/КЕП — по договорённости **[проверить]**.
- Нумерация без пропусков (с резервом «аннулирован»), запрет редактирования выпущенного документа — только сторно/корректировка. Журнал изменений (audit) на всё.
- Все правовые пункты — в `rules`-файлах с годом; в UI — «не налоговая консультация».

## 15. Валидация полей (единый слой)

Один набор валидаторов (zod) для клиента и сервера в `lib/validation/`, сообщения через i18n, покрытие тестами:
- IBAN (длина по стране + mod-97), BIC/SWIFT, UA МФО; **номера карт не хранить** (PCI DSS) — только токены платёжных провайдеров и маска последних 4 цифр; Luhn нужен лишь для проверки ввода у провайдера.
- DE: USt-IdNr (формат + опциональная проверка VIES), Steuernummer, HRB/HRA, PLZ (5 цифр), Handelsregister-номер. UA: ЄДРПОУ (8 цифр, контрольная), ІПН (10/12, контрольная), номер свідоцтва ПДВ, поштовий індекс (5).
- Телефон (libphonenumber, страна из режима), email (синтаксис; MX — опционально), URL, даты, суммы (знаки после запятой по валюте), проценты и ставки, ГТИН/EAN штрихкод (контрольная цифра), HS/УКТ ЗЕД.
- Адрес: структурированные поля (страна, индекс, город, улица, дом, квартира/офис), проверка индекс↔город; UA — привязка к справочнику НП/КОАТУУ.
- Правило: ошибка показывается у поля сразу, отправка блокируется, сервер повторяет проверку (клиенту не верить).

## 16. Автозаполнение: адреса и контрагенты

Интерфейс провайдера `lookup(kind, query, country) → suggestions[]` с кэшем и лимитами; провайдер заменяем в настройках; ручной ввод всегда доступен.
- **Адреса**: UA — Нова Пошта Address API (города, отделения, улицы; уже есть частично) + геокодер; DE — геокодер по ключу (Geoapify/HERE/Mapbox/Google Places — выбрать по условиям лицензии; публичный Nominatim для автодополнения запрещён политикой использования **[проверить]**). Подсказки при вводе (debounce), выбор заполняет все поля структурно.
- **Название фирмы → реквизиты**: UA — открытые данные ЄДР (data.gov.ua) и/или платные API (Opendatabot, YouControl и т.п.) → название, ЄДРПОУ/ІПН, адрес, КВЕД, статус, платник ПДВ (проверка в реестре ДПС). DE — у Handelsregister нет общедоступного API для автокомплита, автоматизированные запросы ограничены; реалистично: VIES (проверка USt-IdNr возвращает имя/адрес), OpenCorporates/North Data/аналоги по ключу, Transparenzregister — только вручную **[проверить условия каждого]**.
- Подтянутые данные — черновик: показать источник и дату, человек подтверждает; GDPR — не хранить лишнего, физлиц не запрашивать.
- **Не проверено** (нужны ключи и лицензии от владельца): все внешние справочники; до этого — интерфейс + моки + ручной ввод.

## 17. Импорт, экспорт и миграция из других CRM

- **Мастер импорта** (общий для товаров, контрагентов, заказов, счетов, остатков, сделок): загрузка CSV/XLSX/XML/JSON → определение формата → сопоставление колонок (сохраняемые шаблоны) → предпросмотр с валидацией по строкам → пробный прогон (dry-run) → импорт с отчётом об ошибках → **откат по номеру пакета**. Идемпотентность: обновление по SKU/внешнему id, без дублей.
- **Каталог товаров одним файлом**: название, SKU, штрихкод, категория, цены (розница/опт/закупка), НДС/ПДВ, единицы, вес/габариты, остатки по складам, варианты, описание (ua/de/en), **картинки** (URL в колонках или ZIP; скачать, оптимизировать, положить в хранилище, показать в карточке и списке), производитель, УКТ ЗЕД/HS. Большие файлы — прямая загрузка в Blob (лимит тела запроса 4.5 МБ), обработка по частям в фоне с прогрессом.
- **Форматы-источники**: UA — Prom.ua (YML/XLS), Rozetka, Horoshop, Checkbox, 1С (CommerceML), Bitrix24, KeyCRM/SalesDrive; DE/общие — Shopify, WooCommerce, Odoo, lexoffice/sevDesk, DATEV Stammdaten, HubSpot, Pipedrive, amoCRM, Google Merchant feed. Для каждого — шаблон сопоставления и пример файла.
- **Экспорт**: CSV/XLSX/JSON по любому списку; DATEV (DE), CommerceML/YML (UA), полный бэкап организации (zip), экспорт для налоговых. Экспорт уважает права ролей.
- **Миграция**: чек-лист «переезд из X»: справочники → товары → остатки на дату → контрагенты → открытые заказы/счета → начальные сальдо.

## 18. Удобство и компактность

- Одна оболочка «Бизнес» с разделами: Продажи · Закупки · Склад · Производство · Финансы · Налоги · Настройки (видимы по включённым модулям и режиму рынка).
- Глобальный поиск и быстрые действия (Ctrl/Cmd-K), массовые операции над списками, сохранённые фильтры, клавиатурный ввод табличных частей, копирование документа, «создать на основании».
- Компактная тёмная тема в стиле проекта, адаптивно с телефона (совместимо с планом мобильных приложений и офлайн, `docs/MOBILE.md`).
