# Подключить агента или бота (для клиентов и для себя)

Любой ИИ-агент или бот подключается к фирме **одним адресом и одним ключом** — без серверов, папок и установки.

## Для клиента (3 шага)

1. **CRM → Настройки → Интеграции → «Подключить агента или бота».** Имя, уровень доступа и разделы:
   * *Только чтение* — агент ищет и читает, ничего не меняет;
   * *Может менять* — создаёт и правит записи (задачи, сделки, контакты, счета, расходы, закупки…);
   * разделы (CRM, задачи, финансы и склад, почта…) — агент видит только отмеченные;
   * галочка **«Спрашивать меня перед изменениями»** (включена по умолчанию): каждое изменение агента появляется в этой же
     карточке («Ждут вашего одобрения») и выполняется только после «Одобрить». Айрис тоже умеет: «что просят агенты?».
2. Нажмите «Создать доступ». Ключ `fsk_…` показывается **один раз** (на сервере хранится только его хеш) — скопируйте вместе с готовой
   строкой подключения.
3. Вставьте в агента.

### Куда вставлять
* **ИИ-клиенты с MCP** (Claude, Cursor, DeepSeek Harness и др.) — в настройки MCP-серверов:
  ```json
  { "mcpServers": { "firmspace": { "url": "https://www.firmspace.de/api/connect/mcp", "headers": { "Authorization": "Bearer fsk_…" } } } }
  ```
  Агент сам увидит список инструментов (поиск контактов и сделок, счета, склад, задачи, отчёты, создание записей…) и их описание.
* **n8n, Zapier, Make, свой скрипт** (REST):
  ```bash
  curl -H "Authorization: Bearer fsk_…" https://www.firmspace.de/api/connect/tools
  curl -X POST -H "Authorization: Bearer fsk_…" -H "Content-Type: application/json" \
       -d '{"query":"Müller"}' https://www.firmspace.de/api/connect/tools/search_contacts
  ```
  Ответ — `{ "status": "done", "result": … }` или `{ "status": "pending_approval", "requestId": … }`, если изменение ждёт одобрения.

Отозвать — кнопка «Отозвать» рядом с ключом: доступ пропадает сразу.

## Что гарантирует платформа
* У каждого ключа **своя роль и свои разделы**: «чтение» = наблюдатель, «может менять» = менеджер; права проверяются так же, как у живого
  сотрудника, и дальше выданных разделов агент не пройдёт.
* Наружу **не отдаются** удаление, массовая чистка и служебные функции экрана Айрис (навигация, память и др.).
* Аргументы каждого вызова проверяются тем же кодом, что и в чате Айрис; все вызовы пишутся в журнал действий (`AiLog`, пометка `agent:<имя>`).
* Лимиты: 120 вызовов в минуту на ключ, 5000 в сутки на фирму. Доступ входит в тарифы с ИИ-ассистентом (Professional).
* Хранится только хеш ключа; ключ нельзя восстановить — при потере создайте новый и отзовите старый.

## Где это в коде
`lib/connect/keys.ts` (ключи, вход), `lib/connect/tools.ts` (набор инструментов, очередь одобрения), `app/api/connect/mcp` (MCP-сервер,
JSON-RPC 2.0 / Streamable HTTP), `app/api/connect/tools[/<имя>]` (REST), `app/api/connect/keys` (управление из CRM),
`components/crm/Settings/ConnectCard.tsx`.

## Платформенные агенты (владелец платформы)
Агенты, которые работают на самой платформе (например, автор статей лендинга из Harness), заводятся отдельно — карточка «Агенты» в тех же
настройках для администратора платформы, см. `docs/AGENTS.md`.

## Секреты фирмы для агента (переменные окружения)

В карточке при создании ключа есть поле «Какие переменные окружения может читать агент» (через запятую; `*` — все; пусто — ни одной). Сами переменные владелец ведёт в
Настройки → Интеграции → «Переменные окружения». Дальше агент:

```bash
curl -s -H "Authorization: Bearer $FIRMSPACE_KEY" https://www.firmspace.de/api/connect/env                    # какие имена доступны
curl -s -H "Authorization: Bearer $FIRMSPACE_KEY" "https://www.firmspace.de/api/connect/env?name=SHIPPING_API_KEY"   # {"name":..,"value":..}
```

В MCP то же самое — инструмент `get_env` (появляется в списке, только если ключу разрешена хотя бы одна переменная). Каждое чтение пишется в журнал действий фирмы.
