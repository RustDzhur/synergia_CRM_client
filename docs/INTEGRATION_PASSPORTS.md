# Подключение интеграций (S5)

**Принцип:** Айрис ведёт подключение и делает всё, что можно без человека. Ключи получает человек в кабинете провайдера, договоры подписывает человек, секреты в чат не вводятся.

## Что есть
- **Реестр паспортов** — `lib/integrations/manifests.ts` (начальные паспорта в коде) + таблица `IntegrationManifest` (накладка: статус, название, источник; меняет администратор платформы через `PUT /api/admin/integration-manifests/:key`). Паспорт: ключ, вид, рынки, статус `available | beta | planned`, поля (секретные отдельно), кабинет провайдера, источник, «нужен договор». Описание и шаги — на 4 языках по виду сервиса.
- **Статусы UZ (ТЗ §6.3):** `available` — только курс ЦБ; ЭСФ-операторы (Didox, Faktura.uz), Payme, Click, Uzum, ATMOS, онлайн-касса, банки — `planned`, кнопки нет, подключить нельзя. Сервис без кода подключения нельзя перевести из `planned` (проверяется маршрутом). Статус `available` ставят только после проверки на живых тестовых ключах.
- **Инструменты Айрис:** `find_integration`, `explain_integration`, `start_integration` (открывает защищённое окно `/crm/settings/integrations?connect=<ключ>`), `verify_integration`, `list_my_integrations`. Все они не записывают данных и не возвращают ключи.
- **Защищённый маршрут** `POST /api/integrations/secrets` — значения идут из окна напрямую на сервер, ошибки провайдера очищаются от введённых значений, в ответе только имя и состояние.
- **Каталог** `GET /api/integrations/catalog` — паспорта для рынка фирмы.

## Что не сделано и почему
- **Универсальный REST-коннектор по паспорту без кода** — нет ни одного реального провайдера с договором и тестовыми ключами, на котором его можно проверить; не строим вслепую.
- **Закрытое объединение `IntegrationType`** остаётся в коде (типы существующих подключений); данные реестра его не заменяют, пока не появятся новые подключаемые сервисы.
- `finish_integration` как отдельный инструмент не нужен: вебхук оплаты и правило «оплата пришла → счёт оплачен» (`registerPayment`) уже работают при подключении платёжных систем.
- Глубокая проверка при `verify_integration` есть у Telegram и WhatsApp; у остальных ключи проверены запросом к провайдеру в момент подключения (результат говорит об этом полем `checked`).

**Payme и Click (UZ)** — статус `beta`, модули в `lib/uzpay/`; инструкция и состав реализованного — docs/UZ_PAYMENTS.md.
