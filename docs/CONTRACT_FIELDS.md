# Шаблоны договоров и поля-меточки

Юрист присылает договоры, фирма превращает их в шаблоны: в нужные места ставятся поля-меточки `{{customerPassportFull}}`, и при создании договора они сами заполняются данными выбранного клиента.

## Где что
- **Настройки → Юридические документы → Шаблоны договоров** (`/crm/settings/legal`): список шаблонов, редактор, «Реквизиты вашей фирмы для договоров».
- **Бухгалтерия → Договоры → Новый договор**: выбрать клиента (контакт или компанию из CRM) и шаблон — панель «Данные для договора» покажет все поля из текста, заполненные из карточки клиента и настроек фирмы; пустые подсвечены.

## Редактор шаблона
1. **Загрузить файл** `.docx` или `.txt` (текст попадает в редактор; файл не сохраняется) либо вставить текст.
2. **Палитра полей** (около 200): по группам, с поиском и фильтром «моя страна + общие» / «все страны». Поле перетаскивается мышью в нужное место текста или вставляется кликом в позицию курсора.
3. **Свои поля** — всё, чего нет в списке (ключ латиницей, подпись, «брать из карточки клиента»).
4. **Предпросмотр** подставляет вместо меток их названия; метки, которых нет ни в каталоге, ни среди своих полей, перечисляются предупреждением (в PDF они останутся как написаны).

## Каталог полей (`lib/finance/contractFields.ts`)
- **Клиент (`customer…`) и наша фирма (`firm…`)** — один набор из ~60 реквизитов на каждую сторону: ФИО по частям, дата и место рождения, гражданство; паспорт (серия, номер, кем и когда выдан, срок), ID-карта, УНЗР, вид на жительство; налоговые и регистрационные номера по странам (UA: РНОКПП, ЄДРПОУ, КВЕД; UZ: ПИНФЛ, СТИР, ОКЕД; DE: Steuer-ID, Steuernummer, USt-IdNr., HRB, Registergericht); адреса (юридический, фактический, составные части); контакты; банк (IBAN, BIC, МФО, расчётный счёт); компания (форма, вид деятельности); представитель (должность, основание, доверенность). Вычисляемые: полное ФИО, фамилия с инициалами, «серия и номер» паспорта.
- **Договор:** номер, дата, сегодняшняя дата, сумма, валюта, начало и конец — подставляются сами.
- **Условия** (вводятся в форме договора): город, предмет, срок, оплата и пеня, гарантия, подсудность; аренда (объект, площадь, кадастровый номер, плата, залог); трудовой (должность, оклад, испытательный срок); купля-продажа/поставка; заём; транспортное средство.
- Поля помечены странами (`UA`, `UZ`, `DE` или все): в палитре по умолчанию видны поля страны фирмы и общие.
- **Синонимы**: `{{Name}}`, `{{address}}`, `{{passport}}`, `{{phone}}`, `{{email}}`, `{{inn}}`, `{{dob}}` и т. п. понимаются как соответствующие поля клиента (`ALIASES`). Регистр не важен.

## Откуда берутся значения (`lib/finance/contractVars.ts`)
По убыванию приоритета: введённое в форме этого договора → реквизиты в карточке клиента (`extra`, затем колонки карточки) → данные фирмы (настройки бухгалтерии и `contractData`). Данные человека берутся из контакта, организации — из компании; общие (адрес, телефон, код) — из компании, если она привязана. Дата в формате ГГГГ-ММ-ДД печатается как дд.мм.гггг.

Хранение: `Contact.extra`, `Company.extra` (новый столбец), `FinanceSettings.contractData` (новый столбец) — JSON «имя реквизита → текст»; записываются через `PATCH /api/contacts/:id`, `/api/companies/:id`, `/api/finance/settings` полем `extra` / `contractData` (пустая строка удаляет ключ). Галочка «Сохранить данные клиента в его карточку» в форме договора записывает введённое туда.

## Не сделано
- Сумма прописью (`{{valueWords}}`): склонения на четырёх языках — отдельная задача.
- Правка реквизитов клиента в самой карточке CRM (сейчас — через форму договора); поля `extra` видны в API карточек.
- Сопоставление полей файла `.docx` с метками автоматически (юрист ставит их в редакторе); таблицы и колонтитулы в `.docx` не разбираются.
