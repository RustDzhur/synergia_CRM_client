# Интеграции: телефония, почта, мессенджеры, онлайн-чат

Все каналы подключаются в **Settings → Integration** (`/crm/settings/integration`), а переписка идёт в
**Collaboration → Chat and Calls** и **Web Mails**. Реквизиты вводит пользователь, сервер проверяет их у провайдера,
хранит **зашифрованными** (AES-256-GCM, ключ — `ENCRYPTION_KEY` или `JWT_SECRET`) и никогда не отдаёт обратно в браузер.

## Что нужно сделать один раз

1. В окружении (локально `.env.local`, на Vercel — Project → Settings → Environment Variables) задать
   `MONGODB_URI`, `JWT_SECRET` и **`APP_URL`** — публичный https-адрес сайта. Без него Telegram, Viber, Twilio и Meta
   не смогут присылать сообщения (на `localhost` они до сервера не дотянутся).
2. Для входа в почту «через Google / Microsoft» добавить `GOOGLE_*` / `MS_*` (см. `.env.example`).
   Без них в Web Mails остаётся вход по паролю приложения.
3. Переразвернуть проект.

## Проверка после деплоя

Откройте `https://ВАШ-САЙТ/api/health`: страница покажет, какие переменные окружения заданы (`MONGODB_URI`, `JWT_SECRET`, `APP_URL`)
и отвечает ли база. Если вход в кабинет не работает — сначала смотрите сюда:

* `MONGODB_URI: false` или `JWT_SECRET: false` — добавьте переменные в Vercel (Project → Settings → Environment Variables) и переразверните.
* `db` пишет про доступ — в MongoDB Atlas откройте Network Access и разрешите `0.0.0.0/0` (Vercel не имеет фиксированного адреса).
* Ответ `401 Protected deployment` от Vercel — включена защита деплоя (Settings → Deployment Protection); открывайте боевой домен проекта.

## Каналы

| Карточка | Что нужно | Что делает CRM |
|---|---|---|
| **Call Provider / SMS Provider** (Twilio) | Account SID, Auth Token, номер Twilio в формате `+49…` | Проверяет номер, сама создаёт API-ключ и TwiML-приложение для звонков из браузера, настраивает вебхуки номера. SMS — в Chat and Calls, звонки — кнопка трубки в беседе, входящие показываются панелью внизу справа |
| **Telegram** | Токен бота от @BotFather | Вызывает `setWebhook` с секретом. Пишут боту — сообщения появляются в Chat and Calls |
| **Viber** | Токен бота (partners.viber.com) | Вызывает `set_webhook`. Подпись каждого запроса проверяется |
| **Messenger** | Page access token и App secret из Meta for Developers | После подключения показывает Callback URL и Verify token — их нужно один раз внести в Webhooks приложения Meta и подписаться на `messages` |
| **Online Chat / Widget For Website** | Ничего внешнего | Показывает готовый код `<script src="…/widget.js" data-token="…">` для вашего сайта |
| Comments, Chat Bot | — | Пока демонстрационные |

Если вебхук зарегистрировать не удалось (например, `APP_URL` ещё не задан), канал получает статус «Needs attention»
и кнопку **Register webhook** — её достаточно нажать после исправления `APP_URL`.

## Почта (Web Mails)

* **Gmail, Yahoo, iCloud, Outlook/Office 365 и любой IMAP** — вход по адресу и **паролю приложения** (не основному паролю).
  Сервер CRM по IMAP забирает последние письма (Входящие и Отправленные), отправляет через SMTP. Новые письма подтягиваются
  раз в минуту и по кнопке «обновить».
* **Gmail и Outlook через OAuth** — если заданы `GOOGLE_*` / `MS_*`, в окне подключения появляется кнопка «Sign in with …».
  Письма читаются и отправляются через API Gmail / Microsoft Graph. Для Gmail выдаваемые права (`gmail.readonly`, `gmail.send`)
  Google относит к ограниченным: приложению в режиме «Testing» доступны только добавленные тестовые пользователи, для остальных
  нужна проверка приложения Google.
* Звезда, «отложено» и удаление действуют **только в CRM**; на почтовом сервере письма остаются нетронутыми.
  Черновики тоже хранятся только в CRM.
* Свой IMAP/SMTP-сервер не может указывать на внутренние адреса (`localhost`, `10.x`, `192.168.x`, `169.254.x`).
  Для локальной проверки с тестовым сервером задайте `MAIL_ALLOW_PRIVATE_HOSTS=1`.

## Свой SIP-провайдер (Call Provider → вкладка «SIP provider»)

Клиент CRM сам выбирает оператора: вместо Twilio подключается любой SIP-провайдер или АТС. Звонки идут **из браузера по SIP через
WebSocket** (RFC 7118, библиотека SIP.js): браузер регистрируется у провайдера и звонит, сервер CRM в разговоре не участвует.

**Что нужно от провайдера** — включённый SIP over WebSocket (`wss://`): Asterisk, FreeSWITCH, 3CX, FusionPBX, Kamailio и многие
облачные АТС. Провайдеры, у которых только SIP по UDP/TCP, из браузера не работают — у них нужно включить WSS или поставить
перед ними АТС. Понадобятся: адрес `wss://…`, SIP-домен, логин (внутренний номер), пароль; при необходимости — отдельный логин авторизации.

* Реквизиты проверяются **до сохранения**: браузер регистрируется у провайдера, и только при успехе CRM их сохраняет (пароль — зашифрованный).
* Если подключены и Twilio, и SIP, в звонилке появляется переключатель провайдера.
* **Звонилка**: кнопка внизу справа → клавиатура как на телефоне, вкладка «Недавние», в разговоре — микрофон, цифры (DTMF), отбой.
  Цифры уходят по RTP (RFC 2833), а если провайдер этого не согласовал — по SIP INFO.
* **Журнал звонков**: каждый звонок (входящий, исходящий, пропущенный, занято, ошибка) записывается в Chat and Calls,
  в список «Недавние» и в ленту активности контакта, если номер совпал с телефоном контакта (сравниваются последние 9 цифр).
  У Twilio журнал пишет сервер по вебхуку, у SIP — браузер после завершения звонка (`POST /api/calls`).
* Ограничения: входящие звонки идут, только пока в браузере открыта вкладка CRM; если вкладку закрыли посреди разговора,
  запись об этом звонке не сохранится; текстовых сообщений у SIP нет (только звонки); пароль SIP отдаётся браузеру владельца
  (`GET /api/sip/credentials`, без кэша), потому что регистрация происходит на стороне браузера.
* Проверено на имитации SIP-сервера (регистрация с Digest-паролем, исходящие, входящие, занято, не найден, отмена, пропущенный, отклонённый, цифры).
  **Не проверено на настоящем провайдере и со звуком** — это нужно один раз сделать на вашем аккаунте.

## Как это устроено

```
Telegram / Viber / Messenger / Twilio ──вебхук──▶ /api/webhooks/<канал>/<токен>   (проверка подписи провайдера)
Посетитель сайта ──widget.js──▶ /api/webchat/<токен>/messages                     (публичный, с лимитом запросов)
                                        │
                                        ▼
                     Conversation + Message (MongoDB)  ◀── /api/conversations  ◀── Chat and Calls (опрос раз в 3–6 с)
Web Mails ──▶ /api/mail/*  ──IMAP/SMTP или Gmail/Graph API──▶ почтовый сервер
```

* Модели: `Integration` (подключение, секреты зашифрованы), `Conversation`, `Message` (в том числе записи о звонках), `MailMessage`.
* Адаптеры каналов — `lib/channels/*`, почты — `lib/mail/*`. Новый канал = один адаптер + строка в `lib/channels/index.ts`.
* «Живые» сообщения — это опрос сервера, потому что на Vercel нет постоянных соединений (websocket).

## Что проверено, а что — нет

Проверено автоматически на локальных имитациях провайдеров и на тестовых IMAP/SMTP-серверах: подключение и ошибки,
подписи вебхуков, приём и отправка, дедупликация, TwiML, JWT-токен для Voice SDK, OAuth-цикл с обновлением токена,
шифрование секретов, защита от инъекций и обращений во внутреннюю сеть; интерфейс — в браузере.

**Не проверено на настоящих аккаунтах** (нужны ваши ключи): живой звонок Twilio с микрофоном, настоящие Telegram/Viber/Meta,
вход через настоящие Google/Microsoft. Реальный Twilio Voice SDK при тестовых ключах дошёл до серверов Twilio и был
корректно отвергнут — то есть код загружается и подключается; голосовой тракт нужно проверить один раз на вашем номере.
