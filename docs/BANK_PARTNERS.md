# Банки и правила сверки (S6/S7 — сокращённый объём)

Условие «точка проверки спроса» из ТЗ убрано решением владельца (docs/TZ_MASTER.md §9): партнёрский кабинет банка и роботы практики выполняются в полном объёме.

## Сделано
- **Единый интерфейс банков** `lib/banks/provider.ts` (`BankProvider`: возможности и выписка). Адаптеры monobank и ПриватБанка вызывают прежние функции — поведение не менялось; маршруты `/api/bank/monobank` и `/api/bank/privatbank` (действие `sync`) теперь идут через общий `syncAccount`. Новый банк = один адаптер + паспорт в реестре интеграций.
- **«Обновить все банки»** `POST /api/bank/sync` — все привязанные счета фирмы; ошибка одного банка не мешает остальным.
- **Правила сверки** (`PracticeRule`, `/api/review/rules`): «контрагент/назначение содержит … → статья». Применяются к новым строкам выписки (в том числе из банка по API) и сразу к неразмеченным; закрытый период не переписывается. Задают владелец, администратор и специалист практики. Правила явные, без самообучения.
- UZ: только импорт выписки файлом (кнопок «подключить по API» нет, пока Центробанк Узбекистана не опубликует правила для сторонних провайдеров).

## Банк-партнёр (S6, полный объём по ТЗ §7.2)
- **Страница и ссылка** `/partner/<код>`: клиент видит банк, код запоминается, после входа в «Финансы → Банк» первым шагом предлагается подключить счёт этого банка; другие банки не скрыты. Атрибуция — `PartnerReferral` (одна запись на банк и фирму).
- **Кабинет банка** `/crm/bank-partner` (сотрудник банка — `BankPartnerMember`, заводит администратор платформы: `POST /api/admin/bank-partners`): воронка (визиты → регистрации → активация = первый счёт → подключён банк), число счетов, коды ссылок. Ни один маршрут `/api/bank-partner/*` не читает данные фирм; тест это проверяет на всех маршрутах роли.
- **Объём платежей через банк** — только по фирмам, отдельно давшим согласие (галочка, по умолчанию выключена; отзыв — в любой момент), и только когда согласившихся не меньше 3 (иначе по числу можно узнать фирму).
- **Лиды по согласию:** клиент сам нажимает «Получить предложение банка», выбирает поля (название, контакт, e-mail, страна), срок до 90 дней; фиксируется в `ConsentRecord` (`bank_lead`). Банк видит только выбранное и только пока согласие действует; отзыв стирает переданное.
- **Согласие на подключение банка:** при привязке счёта создаётся `ConsentRecord` (`bank_connect`); отвязка удаляет токены, прекращает синхронизацию и отзывает согласие.
- **Песочница** `GET /api/bank-partner/sandbox`: тестовая фирма, счёт, выписка и событие вебхука; настоящих данных нет.

## Что нужно от вас (внешнее)
- Завести банк: `POST /api/admin/bank-partners {name, bankProvider, memberEmail}` (сотрудник банка должен сначала зарегистрироваться).
- Договор с банком без эксклюзивности и без доступа к данным клиентов; условия вознаграждения — в переговорах (ТЗ §7.4). Тексты согласий и условий для клиента готовит юрист.

## Не сделано (ждёт внешних условий)
- Агрегатор открытого банкинга для Германии (finAPI) и НБУ — нужны договоры; собственная регистрация не предполагается.
- Роботы практики с откатом пакета, инструменты юриста (хранилище договоров, сравнение версий).
