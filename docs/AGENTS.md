# Агенты, которые пишут для сайта (DeepSeek Harness и др.)

> Для **клиентов и любых агентов, работающих с данными фирмы** (CRM, счета, склад…) есть простой путь — «Подключить агента или бота»
> (MCP-адрес + ключ, без файлов и серверов): `docs/CONNECT.md`. Этот документ — про платформенных агентов (статьи лендинга) и про Harness.

Агент, который работает на сервере (например, в DeepSeek Harness), получает доступ к блогу лендинга отдельным токеном и только
на право «читать список статей и класть статьи в блог». К данным фирм, пользователям, почте и настройкам этот токен не
открывает ничего (`lib/agentBlog.ts`, `app/api/agent/blog/route.ts`).

## Где что лежит (одна площадка)

| Что | Где |
|---|---|
| Harness (определение) | `deploy/agents/` в репозитории сайта; выкладывает тот же `autodeploy.sh` |
| Секреты Harness | `deploy/agents/.env` на сервере (в git нет) |
| Рабочие папки агентов | `~/agents/<имя>/` на сервере; внутри Harness — `/workspace/<имя>` |
| Код сайта для агентов | `/site` внутри Harness, только чтение |
| Токены и права агентов | CRM → Настройки → Интеграции → «Агенты» |

Harness работает в Docker с сетью host, поэтому изнутри сайт виден как `http://127.0.0.1:3210`.

## Завести нового агента (администратор платформы)

1. CRM → Настройки → Интеграции → карточка **«Агенты»**: имя + право (сейчас «Блог: читать статьи, сохранять черновики») →
   «Создать агента». Токен показывается **один раз**: кнопка «Скопировать для агента» кладёт в буфер готовое сообщение (адрес, токен, что можно делать) — вставьте его агенту в чат, он сам сохранит токен в свой `.env`; терминал не нужен. Сервер хранит только его хеш.
2. В Harness создайте агента с рабочей папкой `/workspace/<имя>`; положите туда `.env` (`FIRMSPACE_API=http://127.0.0.1:3210`,
   `FIRMSPACE_TOKEN=<токен>`) и текст задачи (шаблон — `~/agents/_template/TASK.md`).
3. Отозвать — кнопка «Отозвать» в той же карточке: доступ пропадает сразу, ничего перезапускать не нужно.

Каждый агент имеет **свои** токен и права: компрометация одного не открывает остальных. Права выдаются точечно — под каждое
новое право добавляется конкретный маршрут (`lib/agents.ts`, `AGENT_SCOPES`), «доступа ко всему» нет. Старый общий токен
`AGENT_BLOG_TOKEN` в `.env` продолжает работать (право «blog»), но удобнее заводить агентов в CRM.

Статьи сохраняются **черновиками**; публикует администратор платформы командой Айрис: «какие черновики статей есть?»,
«опубликуй статью …» (`list_blog_posts`, `publish_blog_post`). Автопубликация агентом — только при `AGENT_BLOG_AUTOPUBLISH=1`.

## Что отправляет агент

Чтение — какие статьи уже есть (чтобы не повторяться):
```bash
curl -s -H "Authorization: Bearer $AGENT_BLOG_TOKEN" https://www.firmspace.de/api/agent/blog
curl -s -H "Authorization: Bearer $AGENT_BLOG_TOKEN" "https://www.firmspace.de/api/agent/blog?slug=some-slug"
```

Запись — статья на трёх языках (все три обязательны: en, de, ua), текст без HTML:
```bash
curl -s -X POST https://www.firmspace.de/api/agent/blog \
  -H "Authorization: Bearer $AGENT_BLOG_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "slug": "how-to-qualify-leads",
    "title":   { "en": "How to qualify leads", "de": "…", "ua": "…" },
    "excerpt": { "en": "One or two sentences for the blog list", "de": "…", "ua": "…" },
    "body": [
      { "en": "First paragraph", "de": "…", "ua": "…" },
      { "en": "Second paragraph", "de": "…", "ua": "…" }
    ]
  }'
```
Поля: `slug` (латиница, цифры, дефисы; если не задан — строится из английского заголовка), `title` до 160 знаков, `excerpt` до 400,
`body` — до 60 абзацев по 4000 знаков, `image` — только путь вида `/images/blog/имя.jpg` (если не задан — картинка по умолчанию).
Опубликованную статью без `"overwrite": true` перезаписать нельзя (ответ 409). Лимит — 30 записей в час. Ошибки приходят
понятным текстом в поле `message` — агент может сам исправиться.

## Инструкция для агента (вставьте в его задачу)

> Ты автор блога Firmspace AI (платформа для малого бизнеса: CRM, финансы, склад, ИИ-ассистент Айрис). Раз в N дней пиши одну
> статью для лендинга: практичную, без воды, 5–8 абзацев, тема из мира продаж, CRM, учёта, автоматизации. Каждая статья — на
> трёх языках (en, de, ua), текст без HTML и без выдуманных цифр/цен/обещаний про продукт. Перед написанием получи список
> существующих статей (GET) и не повторяй темы. Отправляй статью POST-запросом на `/api/agent/blog` с заголовком
> `Authorization: Bearer <токен>`; она сохранится черновиком — публикует владелец. Токен никуда не выводи и не записывай в файлы.

## Секреты для агентов (право «env»)

Секретные коды, которые вы даёте агентам (пароль почты, токены сервисов, ключи API клиентов), хранятся в админке и **доступны агенту по его токену** —
не нужно прописывать их в файлах Harness.

1. **Внести секрет.** Админка → «Переменные платформы (для агентов)» (общие) или у конкретной фирмы кнопка «Переменные». Имя — `ЗАГЛАВНЫМИ_БУКВАМИ`,
   например `MAIL_PASSWORD`. В базе значение зашифровано; вам оно доступно кнопкой «Показать» (в журнал аудита пишется каждый показ).
2. **Дать агенту право.** У уже созданного агента — кнопка «Права» в списке (токен не меняется, переиздавать его не нужно). Новому — Настройки → Интеграции → «Агенты» → новый агент с правом «Секреты: читать разрешённые переменные» и списком имён через запятую
   (`MAIL_PASSWORD, BLOG_TOKEN`; `*` — все). Агент прочитает только перечисленные.
3. **Как агент читает** (токен — в его `FIRMSPACE_TOKEN`):

   ```bash
   curl -s -H "Authorization: Bearer $FIRMSPACE_TOKEN" "$BASE/api/agent/env"                          # какие имена доступны
   curl -s -H "Authorization: Bearer $FIRMSPACE_TOKEN" "$BASE/api/agent/env?name=MAIL_PASSWORD"       # {"name":..,"value":..}
   curl -s -H "Authorization: Bearer $FIRMSPACE_TOKEN" "$BASE/api/agent/env?org=<id фирмы>&name=SHOP_KEY"  # переменная конкретной фирмы
   ```

Каждое чтение агентом пишется в журнал аудита (кто, какая переменная — без значения), лимит 300 запросов в час на агента. Отзыв агента в настройках
сразу закрывает доступ. Не давайте агенту `*`, если ему нужны две-три переменные.

## Где лежит токен агента

Сервер хранит **только хеш** токена, поэтому увидеть его в CRM после создания нельзя — он показывается один раз. Рабочая копия лежит у самого агента:
`~/agents/<имя>/.env` на сервере (внутри Harness — `/workspace/<имя>/.env`), строка `FIRMSPACE_TOKEN=…`. Файлы созданы от root с правами 0600 — читать их нужно из
Harness или через `sudo`. Если токен потерян — «Отозвать» и создать агента заново (или завести второго): восстановить хеш нельзя.
