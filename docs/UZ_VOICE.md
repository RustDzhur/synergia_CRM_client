# Узбекский голос: как улучшено распознавание

Проблема: браузерное распознавание узбекского (Chrome, `uz-UZ`) ошибается в окончаниях и словах CRM. Что сделано:

1. **Серверное распознавание для узбекского.** Если на сайте настроен ключ распознавания (OpenAI/шлюз или ElevenLabs), узбекская диктовка и режим разговора идут через сервер, а не через браузер. Режим разговора записывает фразу, границу определяет по паузе (1,5 с), отправляет на `/api/ai/transcribe`. Без ключа остаётся браузерное распознавание.
2. **Модель.** У api.openai.com для узбекского используется `gpt-4o-transcribe` (точнее Whisper на редких языках). На шлюзе имя модели задаёт `AI_VOICE_STT_MODEL_UZ`.
3. **Словарь CRM.** Распознавателю передаётся подсказка с узбекскими словами CRM (`mijoz`, `hisob-faktura`, `buyurtma`, `shartnoma`, `vazifa`, …) — он выбирает их, а не созвучные. Эхо подсказки на тишине отбрасывается.
4. **Отдельный распознаватель (необязательно).** `ELEVENLABS_API_KEY` в `.env` — для узбекского ElevenLabs Scribe идёт первым, остальные — запасными.
5. **Терпимость ассистента.** В голосовом режиме модель получила указание трактовать недослышанное по смыслу и словарю CRM.

Что проверить на сервере: `docker compose … up -d --build`, затем сказать несколько команд по-узбекски. Если качество всё ещё плохое — включить `ELEVENLABS_API_KEY` или сравнить модели через `AI_VOICE_STT_MODEL_UZ`. Узбекские сервисы распознавания (Muxlisa, UzbekVoice) не подключены: у них нет публично проверяемой документации API.
