# Firmspace AI — ассистент внутри CRM

Кнопка ✨ в шапке или **Ctrl/⌘ + K** открывает окно ассистента. Он не «чат сам по себе», а слой над данными CRM:
ищет, суммирует, готовит действия. Кнопка **AI summary** в карточке сделки, контакта и компании сразу просит сводку по записи;
кнопка **Analyze** — на письме (Web Mails) и на PDF-документе (Online Documents) — делает то же самое для них.

## Что умеет

| Возможность | Как |
|---|---|
| Поиск по CRM обычными словами | контакты, компании, сделки, письма, «клиенты без общения 30 дней» |
| Сводка по клиенту / сделке / переписке | читает карточку и её историю, письма с адресом; даёт «кто, состояние, открытые вопросы, следующий шаг» |
| Анализ письма (кнопка Analyze) | тип (запрос на покупку / вопрос / другое), приоритет, намерение, краткое резюме; предлагает создать лид или задачу |
| Чтение PDF-документа (кнопка Analyze) | читает текст файла; для трудового договора — находит сотрудника и предлагает сохранить тип договора, дату начала и заметку в его профиль |
| Задачи | «что важнее всего сегодня», «просроченные», «просроченные у Анны» |
| Сотрудники | должность, отдел, число открытых и просроченных задач |
| Действия | создать/изменить задачу, создать сделку, создать контакт, добавить заметку, отправить письмо, сохранить данные договора сотруднику |
| Черновик письма | пишет на языке собеседника; отправка — только после вашего подтверждения, текст можно править прямо в карточке |

Действия **не выполняются, пока вы не нажмёте «Confirm»**. ИИ лишь предлагает карточку с полями; выполняет сервер и от вашего имени.
Исключение — автономный шаг автоматизации, см. ниже.

## Как это устроено

```
Вы ─▶ /api/ai/chat ─▶ цикл: модель ⇄ инструменты чтения (до 6 шагов)
                        │            └─ инструмент записи → НЕ выполняется, превращается в карточку подтверждения
                        ▼
                  ответ + карточки ─▶ окно ассистента
Confirm ─▶ /api/ai/actions ─▶ проверка аргументов и прав заново ─▶ выполнение ─▶ запись в журнал
```

* Инструменты — `lib/ai/tools.ts`: строго типизированные, каждый привязан к разделу CRM. Модель получает **только те инструменты,
  которые разрешены роли пользователя** (сотрудник без раздела Company не получит `list_employees`; наблюдатель — ни одного инструмента записи).
  Модель не имеет доступа к базе напрямую: только к этим функциям, и только к данным вашей фирмы.
* Аргументы от модели считаются недоверенными: длины, даты, адреса и идентификаторы проверяются и при предложении, и при выполнении.
* Текст из писем, заметок и документов — недоверенные данные: в системной подсказке модели запрещено выполнять найденные в них «инструкции».
  Главная защита — не эта подсказка, а то, что любое изменение проходит через ваше подтверждение.
* Журнал (`AiLog`, 180 дней): что читал ИИ, что предложил, что вы подтвердили и что не удалось. Владелец и администратор
  видят его через `GET /api/ai/log`.
* История разговора хранится только в памяти вкладки: ни на сервере, ни в браузере. В браузере запоминаются лишь 4 последних ваших запроса (подсказки «Recent»).
* Лимит: 15 (Free) / 100 (Standard) / 300 (Professional) разговоров в сутки на фирму. Счёт оплаты за модель идёт на владельца платформы,
  поэтому лимит важен; меняется в `lib/ai/run.ts` или переменной `AI_DAILY_LIMIT`.
* Чтение PDF — `lib/ai/pdf.ts` (пакет `pdf-parse`, только текстовый слой; отсканированный PDF без текста возвращает понятную ошибку).
  Извлечённые поля договора хранятся прямо в `Employee` (`contractType`, `contractStart`, `contractNote`) — видны и редактируются
  вручную в карточке сотрудника, не только через ИИ.

## Автономный ИИ-шаг в автоматизации

Automation → правило → действие **«AI decides and acts»**. В отличие от всего остального, это исключение из правила
«ничего без Confirm»: правило автоматизации срабатывает без человека рядом (событие CRM → правило → действие сразу или по расписанию),
поэтому подтверждать нечему. Владелец фирмы, добавляя этот шаг в правило, соглашается на автономное выполнение явно, один раз, при
создании правила (форма показывает предупреждение перед сохранением).

* Модель получает инструкцию из поля правила (не путать с именем правила — это разные вещи) и данные события, может вызвать инструменты
  чтения, затем выполняет **не более одного** инструмента записи — сразу, без карточки. Если не уверена или действие не нужно — ничего не делает.
* Работает с правами владельца фирмы (как и остальные действия автоматизации — move_stage/send_email тоже ничего не спрашивают у роли).
* Тратит ту же дневную квоту, что и обычный чат ассистента — общий счётчик на фирму.
* Результат — в двух местах: журнал автоматизации (Automation → Test Logs, видят все с доступом к разделу) и журнал ИИ (`/api/ai/log`,
  только владелец/администратор, там видно точно что и с какими аргументами выполнилось).
* Проверьте правило кнопкой **Test** перед тем, как включать.

## Как включить

В Vercel (Settings → Environment Variables) добавьте ключ одного провайдера, затем Redeploy:

* `ANTHROPIC_API_KEY` — ключ из console.anthropic.com (модель по умолчанию `claude-sonnet-5`), либо
* `OPENAI_API_KEY` — ключ из platform.openai.com (модель по умолчанию `gpt-4.1-mini`).

Если заданы оба, используется Anthropic; выбрать вручную — `AI_PROVIDER=openai`. Другую модель — `AI_MODEL`. Пока ключа нет,
окно ассистента честно сообщает, что ИИ не включён, ничего не ломается.

## Что проверено, а что — нет

Проверено автоматически (по 36 проверок на каждый из двух адаптеров на основном сценарии, ещё 19 — на чтении PDF, сохранении полей
договора сотруднику и автономном шаге автоматизации, на имитации API модели): цикл инструментов, отказ от выполнения записи
до подтверждения, проверка аргументов, невозможность вызвать несуществующий/запрещённый инструмент, права (владелец / сотрудник / наблюдатель),
изоляция фирм, журнал, лимит (общий между чатом и автоматизацией), автономное выполнение ровно одного действия без подтверждения,
правило без инструкции, ответы при ошибках; интерфейс — в браузере (десктоп и телефон), включая реальную загрузку PDF-файла.

**Не проверено на настоящей модели** (нужен ваш ключ): качество ответов, то, как хорошо модель выбирает инструменты, формулирует сводки
и решает, когда действовать в автономном ИИ-шаге автоматизации; формат ответов реального API (взят из документации Anthropic и OpenAI);
реальная стоимость запросов. После добавления ключа стоит прогнать 6–7 подсказок из окна ассистента на своих данных и один автономный шаг
автоматизации через кнопку «Test», прежде чем включать его на настоящих событиях.

## Пока не сделано
Автоматическая классификация *всех* входящих писем (сейчас — по кнопке Analyze, по вашему запросу: так не расходуется общий лимит и
ваши токены без явного клика), чтение форматов кроме PDF (DOCX, отсканированные изображения), голосовой ввод, показ журнала действий
ИИ в интерфейсе (пока только API — `/api/ai/log`).
